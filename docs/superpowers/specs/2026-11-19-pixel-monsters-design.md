# 몬스터를 점 그림(픽셀아트)으로 — 설계

날짜: 2026-11-19 · 대상 버전: 0.7.0

## 왜 하는가

지금 몬스터는 문자 몇 줄로 그린다. 몸통 모양 12가지에 눈·장식 글자만 바꾸고 속성 색 하나로 칠하기 때문에,
151마리가 사실상 12가지 생김새다. 몬스터를 모으고 키우는 재미가 그림에서 나오지 않는다.

151마리를 **크기도, 모양도, 색도 서로 다른** 점 그림으로 바꾼다.

## 목표 · 하지 않는 것 · 피할 것

**목표**

- 151마리와 알이 모두 점 그림이다. 한 마리마다 그림이 따로 있고, 이름에 맞게 생겼다(여우는 여우, 게는 게).
- 크기가 마리마다 다르고, 진화할수록 커진다. 가장 큰 것도 터미널 8줄을 넘지 않는다.
- 색이 마리마다 다르다. 한 마리 안에서도 외곽선·몸·그늘·눈·무늬를 다른 색으로 칠한다.
- 입력칸 위에서 걷기, 좌우로 돌아보기, 진화 연출(흰빛 깜빡임 → 반짝이)이 지금처럼 동작한다.
- 어두운 터미널과 밝은 터미널 양쪽에서 알아볼 수 있다.

**하지 않는 것**

- 걷는 동작을 마리마다 따로 그리지 않는다. 걷기는 규칙 하나로 만든다(아래 "움직임").
- 새 몬스터, 새 놀이 규칙, 밸런스 변경은 없다. 저장 형식도 그대로다.
- 진짜 이미지(PNG)를 터미널에 띄우는 방식은 쓰지 않는다. Windows 터미널에서 나오지 않는다.

**피할 것 (동작해도 실패)**

- 형제처럼 닮은 그림. 부품을 돌려 쓰거나 색만 바꾼 그림은 안 된다.
- 기존 게임의 캐릭터를 닮은 그림. 이름과 모습은 전부 이 mod 를 위해 새로 짓는다.
- 그림이 커져서 가방의 몬스터 목록이 지금보다 눈에 띄게 줄어드는 것.

## 제약

- 높이는 8줄까지(사용자가 정함). 한 칸을 위아래 반으로 나눠 쓰므로 세로 16점이다.
- mod 는 터미널과 데스크톱 앱 양쪽에서 그려진다(README 가 데스크톱 설치를 안내하고, 테스트도 두 surface 를 돈다).
  터미널에는 글자 칸밖에 없고, 데스크톱에는 벡터 그림(`Svg`)이 있다.
- 가방은 좁은 터미널에서 높이가 빠듯하다(터미널 40줄에서 본문 11줄, 60줄에서 18줄).
- 작업 트리에 0.6.0(중복 Lv.1 한 번에 내보내기)이 커밋되지 않은 채 있다. 이 작업은 그 위에 얹는다.
  커밋은 사용자가 요청할 때만 한다.
- 이 저장소에는 package.json 이 없다. 외부 패키지를 들이지 않는다.

## 만드는 방법: 검토한 세 가지

1. **한 마리씩 직접 그리기 — 선택됨.** 151마리의 점을 하나씩 찍고, 이미지로 뽑아 눈으로 확인하며 고친다.
   마리마다 모양·크기·색이 정말로 다르고 이름과 맞는다. 일이 가장 많다.
   시작 몬스터 다섯 마리로 시험해 보니 그릴 만했고, 사용자가 그 그림을 보고 이 방법을 골랐다.
2. **부품을 조합해 자동으로 만들기.** 몸통·귀·뿔·꼬리를 부품으로 두고 마리마다 조합만 정한다.
   빨리 끝나고 그림체가 고르지만 결국 형제처럼 닮는다. "모양이 다 달라야 한다"와 맞지 않아 뺐다.
3. **이미지 생성 AI 로 그린 뒤 줄여 넣기.** 큰 그림은 화려하지만 16점으로 줄이면 뭉개져서 손으로 다시 찍어야 한다.
   생성 비용이 들고 151장의 그림체를 맞추기 어려워 뺐다.

## 그림 한 장의 모양

그림은 "색 이름표 + 점 줄"이다. 글자 하나가 점 하나이고, `.` 은 빈 칸이다.

```ts
'새싹뿔': {
  palette: { o: '#2f6b3a', a: '#8ad672', b: '#57a655', c: '#d9f2b0', d: '#1f7a3a', l: '#35b24f', L: '#9be870', k: '#17301c' },
  rows: [
    '....dd...',
    '...dlld..',
    '...dlLd..',
    '..oodloo.',
    '.oaaaaaao',
    'oaaaakako',
    'oaaaakako',
    'oaaaaaaao',
    'obaaccaao',
    '.obbbbbo.',
    '.oo...oo.',
  ],
},
```

- 그림은 몬스터 **이름**으로 찾는다(번호는 목록 순서에서 나오므로 순서가 바뀌면 어긋난다).
- 그림 파일은 `hooks/art/` 아래에 계열 묶음별로 나눈다. 그림 파일은 다른 파일을 불러오지 않는 순수한 자료다
  (미리보기 도구가 Node 로 바로 읽기 때문이다).
- 시험으로 그린 다섯 마리(새싹뿔·불씨룡·물방울게·찌릿여우·폭염룡)는 이 문서 맨 아래 부록에 있다.
  사용자가 이 그림을 보고 방법을 골랐으므로 첫 묶음의 출발점이자 그림체의 본보기로 쓴다.

### 그리는 규칙

모든 그림이 한 그림체로 보이도록 지킨다.

- **방향**: 옆모습, 오른쪽을 본다. 게처럼 원래 정면인 것은 정면으로 그린다.
- **크기**: 가로 20점, 세로 15점 이하(걸을 때 1점 뜨는 자리를 남긴다 → 16점 = 8줄).
  빈 테두리 줄·칸은 없앤다.
- **단계별 세로 크기**: 1단계 8~11점, 2단계 10~13점, 3단계 12~15점,
  진화하지 않는 몬스터 10~13점, 전설 13~15점. 이 범위는 길잡이이고 테스트로 막지 않는다.
  - 세로 줄 수는 적게 쓸수록 좋지만 **일부러 낮추지는 않는다**(사용자가 시작 몬스터 12마리를 보고 정함, 2026-11-19).
    낮게 그려도 괜찮은 생김새(게, 도마뱀, 물고기, 뱀, 납작한 벌레처럼 원래 낮은 것)만 낮게 그린다.
    서 있는 새, 나무, 요정처럼 키가 있어야 하는 것을 눌러서 그리지 않는다.
  - 반대로 8줄을 채우려고 일부러 키우지도 않는다.
  - 짝수 점이면 걸을 때 한 줄을 더 쓴다(10점은 6줄, 9점은 5줄). 한 점을 줄여도 모양이 그대로일 때만 홀수로 맞춘다.
  - 꼭 지키는 것은 "진화한 모습은 진화 전보다 칠한 점이 많다" 하나다. 커지는 느낌은 가로와 덩치로도 낼 수 있다.
- **색**: 한 장에 3~8색. 외곽선은 검정이 아니라 몸 색의 어두운 톤. 눈은 세로 2점.
  몸 색은 속성을 떠올리게 하되(불은 붉은 계열, 물은 푸른 계열) 마리마다 다르다.
  같은 계열(진화 줄기)은 색조와 특징(뿔, 등불꽃, 꼬리 끝…)을 이어 가되 색 이름표는 서로 다르다.
- **양쪽 배경**: 어두운 배경(#0c0c0c)과 밝은 배경(#f5f5f5) 둘 다에서 모양이 읽혀야 한다.
  거의 검은 색이나 거의 흰 색만으로 된 부분이 몸 밖으로 튀어나오지 않게 한다.
- **독창성**: 기존 게임 캐릭터가 떠오르면 다시 그린다. (시험 때 불씨룡을 "꼬리에 불이 붙은 주황 도마뱀"으로
  그렸다가 이 이유로 네 발 도마뱀 + 등불꽃으로 바꿨다.)

### 알

알도 점 그림으로 그린다. 4 tick 에 한 번 살짝 기운 그림을 보여 준다(지금의 꿈틀거림과 같은 박자).

## 화면에 그리는 방법

### 터미널: 반칸 블록

한 칸에 점 2개(위·아래)를 넣는다. 글자색이 한쪽 점, 바탕색이 다른 쪽 점이다.

| 위 점 | 아래 점 | 그리는 글자 |
|---|---|---|
| 있음 | 있음 | `▀` 글자색 = 위, 바탕색 = 아래 (두 색이 같아도 이렇게 그린다) |
| 있음 | 없음 | `▀` 글자색 = 위, 바탕색 없음 |
| 없음 | 있음 | `▄` 글자색 = 아래, 바탕색 없음 |
| 없음 | 없음 | 빈 칸 |

- `Text` 의 `color` + `backgroundColor` 로 그린다. 한 줄에서 글자·색이 같은 칸은 하나로 묶는다.
- 그림은 바닥에 맞춘다. 세로 점 수가 홀수면 맨 위에 빈 점 하나가 생긴다.
- `Raster`(칸 격자 전용 요소)는 쓰지 않는다. 터미널 전용이어서 데스크톱에서 아무것도 안 나온다.
- `▀▄` 를 2칸 폭으로 그리게 설정한 터미널에서는 깨진다. 지원하지 않는다(지금의 `▲▼` 버튼도 같은 처지다).
- 색은 24비트 색(truecolor)을 기준으로 고른다. 256색 터미널에서는 가까운 색으로 바뀌어 비슷한 톤이
  뭉칠 수 있다. 따로 맞추지 않는다(지금도 색을 `#rrggbb` 로 준다).

### 데스크톱·그 밖의 surface: Svg

터미널이 아닌 surface 에서는 반칸 글자가 줄 사이 틈 때문에 줄무늬로 보일 수 있다.
그래서 같은 그림 자료로 `Svg` 한 장(점 하나 = 사각형 하나)을 만들어 그린다. 점 하나는 4 CSS px 에서 시작한다.
**이 부분은 만드는 쪽에서 화면을 직접 확인할 수 없다.** 테스트로 그림이 나오는지만 확인하고,
실제 모습은 사용자가 데스크톱 앱에서 본다.

### 움직임

- **걷기**: 짝수 tick 은 바닥에, 홀수 tick 은 1점 떠서 그린다(반칸 단위라 부드럽게 통통 튄다).
  물고기·유령도 같은 규칙으로 둥실거린다.
- **돌아보기**: 점 줄을 좌우로 뒤집는다.
- **진화 연출**: 순서와 문구는 그대로다.
  - 깜빡이는 동안: 칠한 점을 전부 한 색으로 그린다(실루엣). 터미널에서는 테마의 글자색(`text`)을 쓴다.
    어두운 테마에서는 지금처럼 흰빛이고, 밝은 테마에서는 어두운 색이라 사라지지 않는다.
    Svg 에서는 같은 효과를 낼 수 있으면 내고, 안 되면 흰색으로 둔다.
  - 진화 전·후 그림의 높이가 다르므로, 연출 내내 둘 중 큰 쪽 높이로 그려 화면이 흔들리지 않게 한다.
  - 반짝이: 지금처럼 그림 양옆에 `*` `.` 글자를 금색으로 번갈아 붙인다.

## 화면별 변화

### 입력칸 위

- 높이 = 함께 다니는 몬스터의 그림 줄 수(5~8줄) + 상태 줄 1줄. 지금은 4 + 1 로 고정이다.
  함께 다니는 몬스터를 바꾸거나 진화하면 높이가 달라진다.
- 걷는 범위는 지금처럼 "폭 − 그림 폭 − 1".
- **자리가 모자랄 때**: 입력칸 위에 쓸 수 있는 줄 수(`maxRows`)가 "그림 + 상태 줄"보다 적으면 그림을 빼고
  상태 줄만 그린다. 상태 줄과 `가방`·`숨기기` 버튼이 스크롤 밖으로 밀려나면 안 되기 때문이다.
- **가방이 입력칸 위에 떠 있을 때**: 좁은 터미널에서는 가방이 옆이 아니라 입력칸 위에 뜬다.
  첫 묶음에서 실제 터미널로 잰다. 입력칸 위 그림이 커진 만큼 가방의 높이가 줄어든다면,
  가방이 그렇게 떠 있는 동안에는 입력칸 위에 상태 줄만 그린다(목록 길이가 그림보다 먼저다).
  줄어들지 않는다면 아무것도 바꾸지 않는다.

### 가방

그림이 최대 8줄이 되므로, 지금처럼 그림을 설명 위에 쌓으면 목록 자리가 최대 4줄 줄어든다.
좁은 터미널에서는 그림이 거의 항상 빠지게 된다. 그래서 고른 몬스터 부분의 배치를 바꾼다.

- **옆으로 나란히**: 그림을 왼쪽, 이름·진화 안내·버튼을 오른쪽에 둔다.
  이 부분의 높이는 "그림 줄 수"와 "설명 줄 수" 중 큰 쪽이다.
  오른쪽 폭이 24칸 이상일 때 쓴다.
- **위아래로 쌓기**: 오른쪽 폭이 24칸에 못 미치면 지금처럼 그림 아래에 설명을 둔다.
- **촘촘한 배치**: 위 배치로 목록을 3마리도 못 보여 주면, 지금처럼 그림·빈 줄·환율 안내를 뺀다.
- 가방의 그림은 걷지 않는다(바닥에 선 모습).
- 목록만 스크롤되는 동작과 줄 수 계산 방식은 그대로다. 계산에 넣는 그림 줄 수와 설명 폭만 바뀐다.

```
넓을 때                                   좁을 때
  ▄▄████▄▄    No.001 새싹뿔 · 풀 속성       ▄▄████▄▄
 ██▀████▀██   진화: Lv.16 → 덩굴뿔         ██▀████▀██
▄██▄████▄██▄  [ 함께 다니기 ] [ 내보내기 ]  ▄██▄████▄██▄
▀██████████▀                              ▀██████████▀
  ██    ██                                  ██    ██
                                          No.001 새싹뿔 · 풀 속성
                                          진화: Lv.16 → 덩굴뿔
```

## 없어지는 것

- 문자 그림(`hooks/sprite.ts` 의 `BODY`, `crown`, `MIRROR`).
- 몬스터 자료의 `arch`, `accent`, `eye`: 문자 그림만 쓰던 값이다. 그림이 전부 끝난 뒤에 지운다
  (그리는 동안은 "어떤 종류의 생물인지" 힌트로 쓴다).
- `ELEMENT_COLOR`: 그림 색으로만 쓰던 값이라 쓰는 곳이 없어진다.

## 확인하는 방법

**자료 검사(테스트)**

- 151마리 모두 그림이 있고, 몬스터에 없는 이름의 그림은 없다.
- 줄 길이가 모두 같고, 쓰인 글자가 전부 색 이름표에 있고, 이름표의 색이 전부 쓰인다. 색은 `#rrggbb`.
- 크기 한도(가로 20, 세로 15)를 지키고, 빈 테두리가 없다.
- 진화한 모습은 진화 전보다 칠한 점이 많다.
- 점 줄이 똑같은 두 마리가 없고, 색 이름표의 색 집합이 똑같은 두 마리도 없다.

**그리기 검사(테스트)**

- 반칸 변환: 위 표의 네 경우, 좌우 뒤집기, 1점 뜨기, 홀수 높이.
- 입력칸 위·가방에서 터미널과 데스크톱 모두 그림이 나온다.
- 가방 줄 수: 나란히·쌓기·촘촘한 배치 각각에서 목록에 보이는 마릿수가 계산과 맞는다
  (지금 있는 30줄·11줄·6줄 가방 테스트를 새 숫자로 고친다).

**눈으로 확인**

- 미리보기 도구 `tools/sheet.mjs`: 그림 자료를 읽어 어두운 배경·밝은 배경 두 줄짜리 PNG 한 장으로 뽑는다.
  Node 만 쓴다(PNG 는 `node:zlib` 로 직접 쓴다). 그림을 그리는 쪽이 이걸 보고 고친다.
- 실제 터미널: nested `claude --plugin-dir .` 를 pty 로 띄워 입력칸 위와 가방을 확인한다
  (칸마다 글자·글자색·바탕색을 읽어 다시 그림으로 맞춰 본다).

## 진행 순서와 사용자 확인

그림체가 한 번 굳으면 되돌리기 비싸므로 첫 묶음에서 확인받는다.

1. 그리는 틀(그림 자료 형식, 반칸 변환, Svg, 미리보기 도구)과 시작 몬스터 4계열 12마리 + 알.
   → 실제 터미널 화면과 미리보기 이미지를 사용자에게 보여 주고 그림체를 확정한다.
2. 나머지 139마리를 묶음별로 그린다(3단 진화 42 → 2단 진화 74 → 갈래 4 · 진화 없음 14 · 전설 5).
   묶음마다 그리는 쪽이 이미지를 보고 스스로 고친다. 중간에 사용자를 멈춰 세우지 않는다.
3. 전부 끝나면 151마리 전체 이미지를 사용자에게 보여 주고, 마음에 안 드는 것을 짚으면 그것만 다시 그린다.
4. 가방 배치, 없어지는 것 정리, README(놀이 방법·고치기), 버전 0.7.0.

그림이 다 끝나기 전까지는 그림이 없는 몬스터가 있다. 그동안의 처리(임시 그림 등)는 만드는 쪽이 정하되,
마지막에는 임시 처리가 남지 않고 "151마리 모두 그림이 있다" 테스트가 통과해야 한다.

## 만드는 쪽에 맡기는 것

- `hooks/art/` 의 파일 나누기와 묶음 크기, 그림을 찾는 함수의 이름과 모양.
- 반칸 변환·Svg 생성 함수의 이름과 모양, 칸 묶기 방식.
- Svg 의 점 크기(4 CSS px 에서 시작), 알의 기운 그림을 따로 그릴지 규칙으로 만들지.
- 139마리 각각의 생김새(이름·속성·단계·같은 계열의 앞 단계에서 정한다).
- 그림을 여러 작업자가 나눠 그릴지. 나눠 그린다면 1번에서 확정한 12마리를 본보기로 준다.

## 설계자가 정한 것 (사용자가 직접 말하지 않은 것)

사용자가 정한 것은 "151마리가 크기·모양·색이 전부 다르다", "8줄까지", "한 마리씩 직접 그린다" 세 가지다.
아래는 설계자가 정했다. 사용자가 바꿀 수 있다.

- 크기가 진화 단계를 따라 커진다. 가로는 20점까지.
- 걷기를 "1점 뜨기" 규칙 하나로 만든다(그래서 그림 세로는 15점까지).
- 가방에서 그림과 설명을 옆으로 나란히 둔다.
- 데스크톱에서는 `Svg` 로 그린다(직접 확인은 못 한다).
- `arch`·`accent`·`eye`·`ELEMENT_COLOR` 를 지운다.
- 미리보기 도구를 저장소(`tools/`)에 둔다. 나중에 몬스터를 고치거나 더할 때 쓴다.
- 그림체는 첫 12마리에서 한 번, 전체는 끝에서 한 번 확인받는다.
- 입력칸 위에 자리가 모자라면 그림을 빼고 상태 줄만 그린다.
  가방이 입력칸 위에 떠 있고 그림이 가방 높이를 깎는다면, 그동안도 상태 줄만 그린다.
- 24비트 색 터미널을 기준으로 한다. 256색 터미널은 따로 맞추지 않는다.
- 진화 연출의 실루엣은 흰색 고정이 아니라 테마의 글자색으로 그린다(밝은 터미널에서도 보이게).
- 단계별 세로 크기는 길잡이다. 테스트로 막지 않는다.
